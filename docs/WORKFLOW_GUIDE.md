# 한빛유통 · 거래에서 재무제표까지 배우기

## 01. 누구를 위한 공간인가요?

회계 자동화 기술과 회계의 흐름을 공부하고 싶은 사람을 위한 학습 공간입니다. 코딩을 몰라도 가상 한국 도소매 회사 **한빛유통**의 자료로 거래 → 분개 → 검증 → 직접 승인 → 장부 반영 → 재무제표를 따라갈 수 있습니다.

책에서 본 분개가 실제 장부와 보고서로 이어지는 모습을 확인하고, AI의 제안과 사람의 검토가 어떻게 함께 작동하는지 배우기 위해 만들었습니다. 준비부터 보고서까지 같은 학습 순서로 진행합니다.

## 02. 처음 시작 — GitHub 주소와 요청문 하나

[GitHub 저장소 열기](https://github.com/osh3772-star/ledgerflow-ai)

**로그인 여부에 따라 사용하는 요청문이 다릅니다.**

| 현재 상태 | 사용할 요청문 | 연결되는 장부 | 승인하는 곳 |
| --- | --- | --- | --- |
| 비로그인 · 새 체험 | 아래 비로그인 전용 요청문 | 새 임시 회사 · 24시간 | AI가 준 전표별 임시 승인 링크 |
| Google 로그인 완료 | 사이트의 내 Google 장부 연결 요청문 | 지금 사이트에서 보는 내 회사 | 사이트의 사용자 승인 메뉴 |
| 이미 임시 장부 연결됨 | 재설치 없이 같은 AI 폴더에서 학습 계속 | 기존 임시 회사 | 기존 전표별 승인 링크 |

**Google 로그인했다면 아래 비로그인 요청문을 사용하지 마세요.** 사이트 상단 **AI 연결·장부 관리** 또는 **처음 사용하기**에서 **내 Google 장부 연결 요청문 복사**를 누르세요. 10분 일회용 코드가 들어 있어 현재 웹 장부에 바로 연결합니다. 발급받은 AI 연결은 7일이며 사이트에서 취소할 수 있습니다.

이미 게스트로 연습했다면 **같은 AI 작업 폴더**에 개인 요청문을 보내세요. 빈 Google 장부가 있어도 기존 전표가 있는 임시 장부를 연결하며 빈 회사는 삭제하지 않습니다. 또는 기존 임시 승인 화면의 **Google로 이 장부 연결·보관하기**를 사용하세요. 양쪽 모두 작업 기록이 있으면 자동으로 합치거나 덮어쓰지 않고 선택이 필요하다고 알려 줍니다.

연결 후 사이트를 새로고침하고 **상단 회사 ID**와 AI의 **companyId**가 같은지 확인하세요. 최근 MCP 호출과 AI 작성 전표도 그 회사에 대해서만 표시됩니다. 회사가 다르면 분개를 계속하지 말고 개인 연결 요청문으로 다시 연결하세요.

1. 파일과 앱 설정을 다룰 수 있는 **Codex · 코덱스**, **Claude Code · 클로드 코드**, **Antigravity · 안티그래비티** 중 현재 앱을 엽니다. 본인의 앱 계정과 현재 폴더 파일 쓰기 기능이 필요합니다.
2. 해당 요청문을 **AI 대화창에 한 번** 붙여 넣습니다. GitHub 주소도 포함돼 있습니다.
3. AI가 현재 폴더에서 역할 파일과 연결 설정을 준비하고 두 회계 도구를 호출합니다. 로그인한 장부는 전용 코드로, 새 임시 연습은 별도 1,000건 회사로 연결합니다. 폴더 이동은 필요 없습니다.

### 비로그인 전용 · 새 임시 장부 시작 요청문

~~~text
나는 Google 로그인 없이 24시간 임시 장부로 회계 자동화를 체험하고 싶어.
나는 코딩을 모르고 회계 자동화와 회계 흐름을 배우고 싶어.
https://github.com/osh3772-star/ledgerflow-ai
이 저장소의 docs/START_HERE.md를 URL 읽기로 보고, 지금 사용하는 앱의 기본 URL 읽기·현재 폴더 파일 쓰기만으로 학습 환경을 준비해 줘.
git clone·node·터미널 실행·샌드박스 우회·홈 폴더 접근 없이 공개 bootstrap API에서 내 임시 장부와 역할/규칙 번들을 받아 현재 폴더에 병합해 줘. 기존 파일과 다른 MCP 연결은 보존하고 임시 세션 URL은 공개하거나 커밋하지 마.
앱에 맞는 현재 폴더의 MCP 설정 하나를 등록하고, 외부 MCP 스키마 대신 현재 폴더의 docs/MCP_CATALOG.json으로 get_system_status → get_company_context를 호출해 확인해 줘. 앱 자체 허용/갱신이 필요하면 우회하지 말고 남은 상태만 정확히 알려줘.
마지막에 첫 매출 통합 준비 요청문을 보여줘. 이번 설치에서 분개·승인·장부 반영은 하지 마.
이 요청문은 비로그인 체험 전용이야. 내 Google 장부를 연결하려는 작업이면 임시 장부를 만들지 말고 사이트에서 개인 연결 요청문을 받도록 안내해 줘.
~~~

회계 서버·데이터베이스·공공 API 키를 직접 설치하거나 발급받지 않습니다. AI가 URL 읽기와 현재 폴더 파일 쓰기로 임시 장부와 연결을 준비합니다. 터미널·홈 폴더 접근·외부 MCP 스키마 읽기는 기본 경로에 없습니다. 임시 장부는 24시간 동안 접근할 수 있고, 보관하려는 경우에만 Google을 연결합니다. AI 앱 자체의 신뢰 확인·새 연결 읽기는 앱 정책에 따라 필요할 수 있으므로 모든 앱·버전의 무클릭 완료를 보장하지 않습니다.

## 03. 내 장부가 연결됐는지 확인하기

공개 학습 번들을 한 번 받으면 서버에서 내 임시 가상회사와 연습 거래 1,000건이 자동 발급됩니다. 비공개 세션 키로 현재 앱과 해당 회사가 연결됩니다. 다른 사람은 다른 키와 다른 회사로 연습합니다. 키 없이 최초 연결하는 앱도 MCP 세션별로 임시 회사가 배정되지만, 학습을 이어갈 때는 bootstrap이 반환한 세션 전용 주소를 사용합니다.

임시 장부는 24시간 후 접근이 만료됩니다. 자동 삭제를 의미하지는 않습니다. Google 장부 전용 요청문은 10분 코드로 7일짜리 AI 작성 연결을 준비하며 승인 권한을 주지 않습니다. 기본 샘플뿐인 빈 Google 장부는 기존 임시 작업 장부로 연결하고, 양쪽 모두 작업한 장부는 자동 병합하지 않습니다. 임시 링크 승인은 실명 확인이 없으므로 실제 업무용 인증으로 사용하지 않습니다.

| AI가 알려주는 상태 | 의미 | 다음에 할 일 |
| --- | --- | --- |
| 설정 준비됨 | 현재 폴더와 현재 앱의 연결 설정이 병합됨 | AI가 실제 연결 검사를 계속 진행 |
| 로컬 문서 준비됨 | 역할·규칙·핵심 도구 명세가 현재 폴더에 만들어짐 | AI가 외부 파일 대신 이 문서로 직접 도구 호출 |
| 현재 앱 연결 확인됨 | 현재 앱의 두 도구 호출이 실제 성공 | 첫 거래 한 건으로 학습 시작 |
| 앱 새 연결 읽기 대기 | 앱이 실행 중 설정 변경을 읽지 못함 | 앱 고유 새로고침·신뢰 확인이 필요한 경우만 안내받기 |

MCP는 AI가 이 사이트의 회계 도구를 사용하는 통로입니다. 서버를 하나 더 설치하는 뜻이 아닙니다. 첫 연결이 끝나도 거래를 자동으로 전부 처리하지 않습니다. 무엇을 공부할지 AI에게 요청하면서 진행합니다.

## 05. 첫 연습 — 매출 한 건을 설명해 달라고 요청하기

요청은 이 사이트 입력란이 아니라 **연결된 코덱스·클로드 코드·안티그래비티 대화창**에 보냅니다. 새 거래를 먼저 만들 필요는 없습니다.

~~~text
2026년 1월 첫 미처리 매출 한 건으로 회계 공부를 시작하고 싶어.
연결·회사 확인 후 통합 분개 준비 기능으로 거래 선택 → 초안 → 검증 → 승인 요청을 한 번에 준비해 줘. 현재 앱과 같은 학습 요청 키를 함께 전달하고, 반환된 증빙·검증·준비 기록은 다시 조회하거나 중복 기록하지 마.
어떤 거래인지, 어떤 계정에 왜 기록하는지, 공공자료의 실제 조회 여부와 판단의 불확실성을 쉬운 말로 설명해 줘.
승인 링크를 보여주고 멈춰. 링크는 내가 직접 열고 승인할게. 너는 승인하거나 장부에 반영하지 마.
~~~

AI가 찾아온 거래·증빙, 선택한 계정과 이유를 읽습니다. 계산과 오류 검사는 회계 엔진이 수행합니다. AI의 설명이 이해되지 않거나 자료가 부족하면 추가 설명을 요청하세요. 첫 매출은 상태 → 회사 → 통합 준비의 정상 경로 3회 호출로 진행합니다. 반환된 증빙·검증·준비 기록을 반복 조회하지 않으며 오류나 추가 판단은 별도 호출할 수 있습니다. 이 단계는 승인 대기에서 멈춥니다.

## 06. 사이트에서 직접 승인하고 장부에 반영하기

1. **AI 대화창:** 첫 거래 요청문을 보냅니다. 거래 설명·분개 초안·오류 검사 결과와 승인 링크를 받습니다.
2. **승인 링크:** 내가 직접 열어 거래일·계정·금액·증빙을 확인하고 승인 또는 반려 버튼을 누릅니다. Google 장부는 로그인한 사이트의 사용자 승인에서, 임시 장부는 전표별 임시 화면에서 진행합니다. 링크를 공유하거나 AI에게 대신 승인하게 하지 마세요.
3. **AI 대화창:** 승인 후 장부 반영 요청문을 보냅니다.
4. **같은 회사의 사이트:** 새로고침 → 2026년 1월 → 재무 보고서에서 바뀐 숫자를 확인합니다.

승인 전에 거래일·귀속 월·계정·금액·증빙, 차변과 대변 합계가 맞는지 확인합니다. 전표 ID·버전·내용 확인값은 같은 기록을 승인하는지 확인하는 표시입니다. 내용을 이해하지 못했다면 먼저 설명을 요청하세요. 맞지 않으면 반려합니다.

**앱에서 도구 실행을 허용하는 것과 전표를 승인하는 것은 다릅니다.** 전표 승인은 이 사이트에서 직접 합니다. AI가 내 승인 버튼을 대신 누르지 않습니다.

~~~text
방금 연습한 전표를 사이트에서 직접 승인했어.
그 전표의 승인 상태와 내용이 그대로인지 확인하고, 승인된 경우에만 장부에 반영해 줘.
실제 반영 완료 상태를 확인한 뒤 2026년 1월 시산표와 재무제표를 보여줘.
바뀐 숫자와 그 이유를 회계 초보자에게 설명해 줘. 미승인·반려된 전표는 반영하지 마.
~~~

실제로 장부에 반영된 기록만 ‘Posted · 장부 반영 완료’입니다. 반영 요청 중 오류가 나면 기존 전표 상태부터 확인하고 중복 전표를 새로 만들지 않습니다.

## 07. 숫자로 이해하기 — 거래와 보고서는 어떻게 이어지나요?

아래는 **공급가액 100만 원, 부가세 10만 원, 아직 돈을 받지 않은 판매**의 매출 부분을 단순화한 학습 예제입니다. 상품원가 등 추가 기록과 실제 금액은 AI가 조회한 거래·증빙을 기준으로 확인하세요.

| 기록하는 쪽 | 계정 | 금액 | 쉬운 설명 |
| --- | --- | --- | --- |
| 차변 | 매출채권 | 1,100,000원 | 나중에 고객에게 받을 돈 |
| 대변 | 상품매출 | 1,000,000원 | 상품을 팔아 생긴 수익 |
| 대변 | 부가세예수금 | 100,000원 | 판매에 따라 생긴 부가세 관련 부채 |

두 쪽의 합계는 각각 110만 원입니다. 장부 반영 후 시산표에서는 세 계정의 기록을, 재무상태표에서는 받을 돈과 부채의 변화를, 손익계산서에서는 매출을 확인합니다. 나중에 수금하는 거래는 매출을 다시 만들지 않고 받을 돈과 예금을 연결해 봅니다.

거래 1,000건은 연습할 **원천 자료**입니다. 초안·승인 대기는 보고서에 포함되지 않습니다. 장부에 반영한 전표만 숫자에 반영되므로 처음에는 ‘장부 반영 전’으로 보이는 것이 맞습니다. 시산표는 선택 기간의 기록, 재무상태표는 기준일까지의 자산·부채·자본, 손익계산서는 선택 기간의 수익·비용을 보여줍니다.

## 08. 한 달 정리와 월말 결산으로 넓히기

한 건의 흐름을 이해했다면 매출·매입·수금·지급이 섞인 1월 전체로 넓혀보세요.

~~~text
이제 2026년 1월 전체 거래를 공부하고 싶어. 실제 연결과 내 회사를 먼저 확인해 줘.
이미 처리한 거래와 기존 초안을 확인해서 중복을 피하고, 필요한 회계 역할을 순서대로 사용해 줘.
증빙과 공공 참고자료를 확인한 뒤 분개 초안 → 오류 검사 → 내 승인 요청까지 준비해 줘.
자료가 부족한 거래는 따로 남기고, 처리한 건수와 내가 검토할 내용을 쉬운 말로 설명해 줘.
내 승인 대기에서 멈추고, 기간 마감은 하지 마.
~~~

내가 승인한 처리 목록의 장부 반영을 요청한 뒤 보고서를 확인합니다. 월말에는 감가상각·선급비용·미지급 항목처럼 그 달에 맞춰 조정할 내용을 따로 검토합니다. 수정분개도 같은 승인 절차를 거칩니다. 기간 마감은 그 기간의 추가 기록을 막는 단계이므로 별도로 요청합니다.

## 09. AI의 여섯 역할은 어떻게 쓰이나요?

| 역할 | 공부할 내용 |
| --- | --- |
| 총괄 | 할 일과 처리 순서 |
| 매출 | 판매, 매출채권과 수익인식의 근거 |
| 매입 | 매입, 매입채무와 증빙 중복 |
| 자금 | 입출금과 받을 돈·줄 돈의 대조 |
| 결산 | 월말 수정·보고서·마감 |
| 감사 | 중복·누락·기간 오류 점검 |

시작 설정에서 기존 역할 파일을 준비합니다. AI가 현재 대화에서 필요한 역할을 순서대로 사용하며 여섯 AI가 항상 동시에 실행되는 것은 아닙니다. ‘이번에 실제 사용한 역할과 도구를 알려줘’라고 물어 확인하세요. 역할 파일 설치, 역할 사용, 실제 도구 호출은 구분합니다.

## 10. 공공 API 자료는 어디에 쓰이나요?

연결 후에는 사이트에 준비된 공공자료 기능을 사용합니다. 별도 API 키를 발급받거나 입력하지 않습니다. 관련 자료만 조회하며 모든 전표마다 네 기관을 전부 호출하지 않습니다.

| 자료 | 학습할 쓰임 | 알아둘 점 |
| --- | --- | --- |
| 국세청 | 실제 사업자번호가 있을 때 거래처 상태 확인 | 가상 거래처에는 실제 번호가 없어 조회 제외 |
| DART · 금융감독원 | 공시기업 재무·공시 비교 | 해당 기업의 매출을 내 가상회사 장부로 가져오지 않음 |
| 국가법령정보 | 거래일에 맞는 법령·시행일 참고 | 조문 조회만으로 회계·세무 판단을 확정하지 않음 |
| ECOS · 한국은행 | 환율·금리·경제통계 참고 | 모든 통계가 모든 분개 금액에 반영되지는 않음 |

‘실제 조회 / 샘플 / 확인 필요 / 조회 제외’, 출처·조회 시각·적용 기준일을 읽어보세요. 연습 장부에 들어가기 전의 공공자료는 보관된 예시이며, 개인 장부에서 거래를 선택하거나 새 분개를 준비할 때 관련 자료를 조회합니다. 자료 조회 실패를 가짜 성공으로 바꾸지는 않습니다.

## 11. 자주 묻는 질문과 막혔을 때

| 궁금한 점 | 확인할 내용 |
| --- | --- |
| 다른 사람이 연습하면 내 장부도 바뀌나요? | 임시 세션 키별로 회사가 다릅니다. 보관한 개인 장부는 Google 계정별로 분리됩니다. 공통 예시는 읽기 전용입니다. |
| 설정 파일을 만들었는데 거래를 못 읽어요. | 앱의 새 연결 읽기·임시 키 만료를 확인합니다. 현재 폴더의 핵심 명세와 현재 앱의 status/context 호출 성공을 확인합니다. |
| 승인했는데 보고서가 그대로예요. | AI에게 승인 후 장부 반영을 요청했는지, 실제 Posted인지 확인하고 해당 월을 선택해 새로고침합니다. |
| 중간에 멈췄어요. | 기존 거래·전표 ID와 현재 상태부터 확인하게 합니다. 이미 반영한 거래를 새로 처리하지 않습니다. |
| 잘못 반영했어요. | 기존 게시 전표를 덮어쓰지 않고 역분개 초안과 별도 승인 절차를 검토합니다. |
| 임시 세션이 만료됐어요. | 같은 시작 요청문으로 새 연습 공간을 준비합니다. 이전 기록을 계속 보관하려면 만료 전에 Google 연결을 선택하세요. |
| 추가 유료 AI API가 필요한가요? | 이 프로젝트용 모델 API 키는 필요 없습니다. 본인의 AI 앱 계정과 이용 한도는 별도입니다. |
| 사이트가 알아서 매일 처리하나요? | 아닙니다. 내가 AI 앱에 요청해 실행하고 직접 승인합니다. 무인 스케줄러는 없습니다. |

## 12. 처음 보는 용어와 더 공부할 자료

| 용어 | 쉬운 뜻 |
| --- | --- |
| ERP | 판매·구매·재고·입출금 등을 모은 회사 업무 자료 |

| 시산표 | 계정별 차변·대변·잔액을 모아 확인하는 표 |
