# 처음 시작하기 — GitHub 주소와 요청문 하나

회계 자동화 기술과 회계의 흐름을 공부하고 싶은 사람을 위한 학습 공간입니다. 코딩을 몰라도 가상 한국 도소매 회사 **한빛유통**의 자료로 거래 → 분개 → 검증 → 직접 승인 → 장부 반영 → 재무제표를 따라갈 수 있습니다.

[사이트 열기](https://ledgerflow-public-reference-gateway.eric5833.workers.dev/) · [GitHub 저장소](https://github.com/osh3772-star/ledgerflow-ai)

## 시작 요청문을 한 번 보내세요

**로그인 여부에 따라 사용하는 요청문이 다릅니다.**

| 현재 상태 | 사용할 요청문 | 연결되는 장부 | 승인하는 곳 |
| --- | --- | --- | --- |
| 비로그인 · 새 체험 | 아래 비로그인 전용 요청문 | 새 임시 회사 · 24시간 | AI가 준 전표별 임시 승인 링크 |
| Google 로그인 완료 | 사이트의 내 Google 장부 연결 요청문 | 지금 사이트에서 보는 내 회사 | 사이트의 사용자 승인 메뉴 |
| 이미 임시 장부 연결됨 | 재설치 없이 같은 AI 폴더에서 학습 계속 | 기존 임시 회사 | 기존 전표별 승인 링크 |

**Google 로그인했다면 아래 비로그인 요청문을 사용하지 마세요.** 사이트 상단 **AI 연결·장부 관리** 또는 **처음 사용하기**에서 **내 Google 장부 연결 요청문 복사**를 누르세요. 10분 일회용 코드가 들어 있어 현재 웹 장부에 바로 연결합니다. 발급받은 AI 연결은 7일이며 사이트에서 취소할 수 있습니다.

이미 게스트로 연습했다면 **같은 AI 작업 폴더**에 개인 요청문을 보내세요. 빈 Google 장부가 있어도 기존 전표가 있는 임시 장부를 연결하며 빈 회사는 삭제하지 않습니다. 또는 기존 임시 승인 화면의 **Google로 이 장부 연결·보관하기**를 사용하세요. 양쪽 모두 작업 기록이 있으면 자동으로 합치거나 덮어쓰지 않고 선택이 필요하다고 알려 줍니다.

연결 후 사이트를 새로고침하고 **상단 회사 ID**와 AI의 **companyId**가 같은지 확인하세요. 최근 MCP 호출과 AI 작성 전표도 그 회사에 대해서만 표시됩니다. 회사가 다르면 분개를 계속하지 말고 개인 연결 요청문으로 다시 연결하세요.

1. 파일과 앱 설정을 다룰 수 있는 **Codex · 코덱스**, **Claude Code · 클로드 코드**, **Antigravity · 안티그래비티** 중 현재 앱을 엽니다. 본인의 앱 계정과 현재 폴더 파일 쓰기 기능이 필요합니다.
2. 해당 요청문을 **AI 대화창에 한 번** 붙여 넣습니다. GitHub 주소도 포함돼 있습니다.
3. AI가 현재 폴더에서 역할 파일과 연결 설정을 준비하고 두 회계 도구를 호출합니다. 로그인한 장부는 전용 코드로, 새 임시 연습은 별도 1,000건 회사로 연결합니다. 폴더 이동은 필요 없습니다.

### 비로그인 전용 · 새 임시 장부 시작 요청문

```text
나는 Google 로그인 없이 24시간 임시 장부로 회계 자동화를 체험하고 싶어.
나는 코딩을 모르고 회계 자동화와 회계 흐름을 배우고 싶어.
https://github.com/osh3772-star/ledgerflow-ai
이 저장소의 docs/START_HERE.md를 URL 읽기로 보고, 공개 bootstrap API에서 역할·규칙·연결 번들을 받아 현재 폴더에 기존 파일을 보존하며 병합해 줘. 기존 연결이 유효하면 재사용하고 새 장부를 만들지 마.
Codex이면 workspacePath=현재 폴더 절대 경로도 전달하고 번들의 .ledgerflow/connect-codex.mjs를 한 번 실행해 공식 Codex CLI가 현재 학습 폴더만 신뢰 등록하고 ledgerflow-accounting-mcp 한 항목을 자동 등록한 뒤 실행 중 앱의 재읽기를 시도하게 해 줘. 다른 폴더의 신뢰·도구 승인 정책과 다른 MCP 연결은 보존해. 내가 MCP 등록·Restart 메뉴를 찾거나 주소를 입력하게 하지 마. Claude Code·Antigravity는 해당 앱의 현재 폴더 설정을 사용해.
홈 설정·인증 저장소·외부 MCP 스키마를 파일 도구로 열지 마. git clone·추가 서버·유료 모델 API·앱 강제 종료·권한 우회는 하지 마. 도우미 1회 실행 외에 불필요한 터미널 명령은 하지 마.
실제 get_system_status → get_company_context 성공과 같은 회사인지 확인해 줘. 파일 준비·CLI 등록·SDK 검사는 실제 앱 연결 성공과 구분하고, 지원되지 않는 재읽기를 성공이라고 하지 마.
마지막에 첫 매출 연습 요청문을 보여줘. 이번 설치에서 분개·승인·장부 반영은 하지 마.
이 요청문은 비로그인 체험 전용이야. 내 Google 장부를 쓰려는 작업이면 임시 장부를 만들지 말고 사이트의 개인 연결 요청문을 사용하게 해 줘.
```

회계 서버·데이터베이스·공공 API 키를 직접 설치하거나 발급받지 않습니다. AI가 URL 읽기와 현재 폴더 파일 쓰기로 장부와 연결을 준비하고 Codex에서는 도우미를 한 번 실행합니다. Node 런타임과 공식 Codex CLI가 필요하며 앱 제공 런타임을 우선 사용합니다. 홈 설정·인증 저장소·외부 MCP 스키마는 일반 파일 도구로 읽지 않습니다. 임시 장부는 24시간 동안 접근할 수 있고, 보관하려는 경우에만 Google을 연결합니다. AI 앱 자체의 신뢰 확인·새 연결 읽기는 앱 정책에 따라 필요할 수 있으므로 모든 앱·버전의 무클릭 완료를 보장하지 않습니다.

## 어디까지 끝났는지 이렇게 확인하세요

| AI가 알려주는 상태 | 의미 | 다음에 할 일 |
| --- | --- | --- |
| 설정 준비됨 | 현재 폴더와 현재 앱의 연결 설정이 병합됨 | AI가 실제 연결 검사를 계속 진행 |
| 로컬 문서 준비됨 | 역할·규칙·핵심 도구 명세가 현재 폴더에 만들어짐 | AI가 외부 파일 대신 이 문서로 직접 도구 호출 |
| 현재 앱 연결 확인됨 | 현재 앱의 두 도구 호출이 실제 성공 | 첫 거래 한 건으로 학습 시작 |
| 앱 새 연결 읽기 대기 | 앱이 실행 중 설정 변경을 읽지 못함 | AI가 기존 연결 도우미로 자동 등록·재읽기를 시도하고 실패 원인을 보고 |

‘설치했다’는 설명이나 파일 목록만으로 연결이 끝났다고 판단하지 마세요. 문서·설정 준비와 현재 앱의 실제 도구 호출은 서로 다른 단계입니다. Codex에서 도구가 안 보이면 사이트의 **Codex 자동 연결 복구 요청문**을 기존 AI 대화에 보내세요. AI가 기존 키로 현재 학습 폴더만 신뢰 등록하고 주소를 자동 등록한 뒤 실행 중 앱의 재읽기를 시도합니다. 수동 등록 메뉴/주소 입력은 제외했습니다. 설정 기록/별도 SDK 검사와 현재 앱 호출은 구분하며, 제어 연결에 접근하지 못하면 실제 연결 성공으로 보고하지 않습니다. 새 게스트를 만들지 않습니다. Google 로그인은 임시 연습에 필요 없습니다.

## 이미 설치했는데 Codex 도구가 없다면

새 장부를 만들지 말고 아래 요청문을 기존 AI 대화에 보내세요.

```text
기존 Codex 회계 연결을 자동으로 복구해 줘. 새로 설치하거나 새 게스트·회사·개인 코드를 발급하지 마.
현재 폴더의 .ledgerflow/guest-session.json과 .codex/config.toml에 있는 기존 연결을 그대로 사용해.
https://ledgerflow-public-reference-gateway.eric5833.workers.dev/connect-codex.mjs 를 URL 읽기로 받아 현재 폴더의 .ledgerflow/connect-codex.mjs에 저장한 뒤 한 번 실행해 줘. 이 도우미가 공식 Codex CLI로 현재 학습 폴더만 신뢰 등록하고 ledgerflow-accounting-mcp 한 항목을 앱에 자동 등록한 뒤 실행 중 앱의 설정 재읽기를 시도하는 것을 허용해. 다른 폴더의 신뢰·도구 승인 정책과 다른 MCP 설정은 보존해.
내가 MCP 등록·Restart 메뉴를 찾거나 주소를 입력하게 하지 마. 홈 설정·인증 저장소·외부 스키마를 파일 도구로 읽지 말고, 앱 강제 종료·새 app-server·새 대화·무인 작업·권한 자동 허용은 하지 마.
configurationRegistered와 nativeClientVerified를 구분해서 보고해. 실제 실행 중 앱의 현재 대화에서 get_system_status → get_company_context 호출과 기존 회사 일치가 성공한 경우에만 실제 연결 완료라고 해. 앱 제어 연결을 지원하지 않으면 정확한 원인을 알려주고 SDK 검사로 성공을 꾸미지 마.
이번에는 연결 확인만 하고 거래 생성·분개·승인·장부 반영은 하지 마. 연결 키와 비공개 URL은 출력하거나 커밋하지 마.
```

## 연결됐다면 첫 거래를 공부하세요

1. **AI 대화창:** 첫 거래 요청문을 보냅니다. 거래 설명·분개 초안·오류 검사 결과와 승인 링크를 받습니다.
2. **승인 링크:** 내가 직접 열어 거래일·계정·금액·증빙을 확인하고 승인 또는 반려 버튼을 누릅니다. Google 장부는 로그인한 사이트의 사용자 승인에서, 임시 장부는 전표별 임시 화면에서 진행합니다. 링크를 공유하거나 AI에게 대신 승인하게 하지 마세요.
3. **AI 대화창:** 승인 후 장부 반영 요청문을 보냅니다.
4. **같은 회사의 사이트:** 새로고침 → 2026년 1월 → 재무 보고서에서 바뀐 숫자를 확인합니다.

요청문과 예제는 [전체 학습 순서](WORKFLOW_GUIDE.md)에 있습니다. 한 건을 이해한 뒤 한 달 정리·결산·감사 점검으로 넓혀보세요.
