# P2-B1 — 가상 ERP 1,000건 생성·참조 검증

2026-10-14 완료한 최소 단위는 **전체 가상 ERP JSON fixture 생성과 독립 참조·금액 검증**이다.
보조원장의 PostgreSQL 테이블·적재·RLS는 다음 P2-B2에 구현한다.
> 이후 [P2-B2 관계형 적재·검증](PHASE_2B2.md)을 완료했다. 이 문서는 P2-B1 당시 기록으로 유지한다.
P2-A 10건의 DB demo는 계속 유지한다. Phase 2 전체 완료나 전표 생성 완료를 의미하지 않는다.

## 생성 결과

```powershell
pnpm seed:full
pnpm check
```

출력: `.ledgerflow/seed-full.json`, seed `20261014`, 버전 `lf-erp-1000-v1`.
가상회사 1,000건과 격리 테스트 회사 별도 1건, 총 1,001건이다.
같은 seed로 두 프로세스에서 재생성한 SHA-256:
`7b39cbe1ca5695767702c02b61b4222799f2df8a08a38a22151cd1bd1e9f0820`.
미니 fixture와 회사·거래 UUID namespace를 구분하여 적재 시 혼합을 방지한다.

실제 공공 API 응답과 독립적으로 생성한다.

## 검증 결과

TypeScript 검사 및 **71개 테스트 / 6개 파일** 통과, 총 13.49초.
이 수에는 기존 PostgreSQL/RLS 테스트와 API 진단의 mock 테스트가 포함된다.
**1,000건 자체를 PostgreSQL에 적재한 결과는 아니다.**

1,000건 fixture 검사 항목:

- 고정 seed의 payload/hash 재현, 다른 seed의 결과 변경, 엔터티 UUID·멱등성 키 유일성.
- 거래별 증빙 hash·같은 회사 참조·월별 기간·정확한 KRW 금액.
- 세금계산서 총액과 명세행 수량×단가, 거래처·상품의 회사 일치.
- 매출계약 인도일과 수익 인식 가정의 일치.
- 모든 상품 거래의 재고 연결, 시간 순서 재고 음수 방지.
- 일부·전액 수금/지급, 세금계산서 초과 배분 방지, 은행 방향·금액 대사.
- 일별 은행 마감 잔액 음수 방지, 자본금 5억원의 계좌별 분할, 급여 원천징수 분리.
- 자산 내용연수·잔존가치·상각 제안, 선급비용의 기간/원가 한도, 미지급비용의 역분개 예정일.
- 별도 작성한 정답 매출 fixture: 매출채권 3,080원, 매출 2,800원, 부가세 280원, 매출원가 2,000원.

정답 fixture는 생성기에서 계산해 복제하지 않았다. 회계 엔진 실행·정답 분개 정확도 평가는 Phase 3 이후 수행한다.

## 적용 가정과 한계

상품/PPE 부가세 10%는 데이터 시나리오 가정이며 세법상 공제·과세 여부를 검증한 결과가 아니다.
급여 원천징수 금액도 시나리오 값이다.
상품 원가는 SKU별 일정하며 인도 완료·수행의무 1개를 수익인식 가정으로 둔다.
감가상각은 사용 가능 월부터 60개월 정액법을 가정하고 회계 검토가 필요하다.

수정 제안 59건은 48건의 감가상각과 11건의 선급비용 상각 예시다.
전체 자산·선급비용의 12월까지 상각이 모두 포함된 완결 장부가 아니며,
회계 코어가 기존 제안과 중복되지 않게 추가 결산 필요액을 계산해야 한다.
전표·승인·전기·법인세·결산 재무제표는 아직 생성하지 않는다.
